Verbatim priority list the user pasted this session (P0–P8, 47 numbered

## P0 — Fix the foundation first
1. Fix packaging (wheel excludes evidence/reconstruction/perception/exporters/sdk/apps; no `reality` console script) — **DONE 2026-09-14, see CURRENT_STATE.md**
2. Reconcile all documentation (README.md, ARCHITECTURE.md, IMPLEMENTATION_STATUS.md, docs/**, */README.md) against actual implementation — what/math/inputs/outputs/units/frame/uncertainty/assumptions/failure/deps/tests/missing
3. Fix source identity — canonical `Source` (source_id, source_type, content_identity, acquisition_id, device_id, capabilities, timestamps, coordinate_frame, calibration, provenance); reconcile `MultiSourceSession.source_id` vs `EvidenceSource`

## P1 — Complete the actual reality-mapping engine
4. Universal source ingestion: stronger phone/drone packages, RGB-D, depth streams, IMU, GNSS, calibration, telemetry, 360°, LAZ, other point-cloud formats — ingesting/using, not just recognizing a folder
5. Real sensor-sidecar ingestion — actual parsers/normalizers for IMU/GPS/GNSS/depth/camera calibration/drone telemetry/timestamps into structured streams
6. Time synchronization — `SensorStream`/`Timestamp`/`ClockModel`/`SynchronizationResult`, `t_normalized = f(t_sensor, clock_offset, clock_drift)` with uncertainty
7. Camera calibration maturity — intrinsics/extrinsics/distortion/sensor dims/resolution/camera-to-IMU/camera-to-LiDAR transforms + reprojection-residual-based quality (mean/median/p95/per-camera/spatial distribution)
8. VIO / visual-inertial localization — RGB+IMU+calibration → 6-DoF trajectory + uncertainty; eventually +GNSS
9. SLAM/trajectory system — Frame/Pose/Trajectory/Landmark/Keyframe/loop closure/covariance/tracking state (TRACKING/LOST/RELOCALIZING/LOCALIZED) + measurable trajectory quality
10. Cross-source registration — align phone/drone/LiDAR/DSLR/RGB-D into one world frame (T_world_phone etc + uncertainty) via GNSS/feature-matching/ICP/trajectory-alignment/control-points/geometric optimization
11. Dense multi-view reconstruction — registered cameras → dense matching → depth maps → depth fusion → dense cloud → surface reconstruction → mesh, with quality diagnostics
12. Canonical `MeshData` — vertices/normals/UVs/indices/materials/submeshes/bounds/coordinate_frame/units/artifact_id, flowing through ArtifactStore → WorldIR.Geometry as a first-class type, not incidental
13. Mesh validation — degenerate triangles, non-manifold edges, bad normals, self-intersections, holes, disconnected components, bad scale/bounds; "mesh quality ≠ mesh existence"

## P2 — Turn perception into real world understanding
14. Better object identity — appearance + geometry + multi-view consistency + spatial constraints + temporal continuity + re-identification → one persistent entity across views
15. Temporal tracking — object/camera/scene tracks with track_id/state/velocity/history/confidence/uncertainty
16. Structural semantic perception — doors/windows/stairs/columns/beams/walls/floors/ceilings/roofs/roads/curbs/sidewalks/infrastructure/terrain/vegetation, from geometry+visual+context (not label-only)
17. Materials as a real perception subsystem — observed appearance vs inferred physical material, from RGB/texture/reflectance/geometry/lighting/context → `MaterialHypothesis` with confidence/provenance/uncertainty

## P3 — Evidence intelligence
18. Real evidence fusion across phone/drone/LiDAR/RGB-D/GNSS/IMU with source reliability, measurement noise, registration uncertainty, timestamp uncertainty, conflicting measurements
19. Proper uncertainty propagation — Σ_camera → Σ_pose → Σ_depth → Σ_point → Σ_registration → Σ_object, not a single scalar confidence
20. Provenance graph — RAW PHOTO → FRAME → CAMERA POSE → DEPTH → 3D POINTS → OBJECT HYPOTHESIS → WORLDIR ENTITY, answering "why does this exist?"
21. Conflict detection — overlapping uncertainty fuses; non-overlapping flags CONFLICT rather than silently averaging
22. Completeness/coverage estimation — what was/wasn't observed, blind spots, weakly-reconstructed surfaces, per-region observed %

## P4 — Persistent World
23. WorldStore — split into WorldStore/SourceStore/EvidenceStore/ObservationStore/ArtifactStore instead of one session JSON
24. ObservationStore — durable `Observation` records (observation_id, entity_id, source_id, timestamp, geometry, measurement, confidence, uncertainty, provenance)
25. Entity history — per-entity observation timeline / state history
26. Incremental world updates — add a source and update the world without full rebuild
27. World diff — v1→v2 added/removed/moved entities, changed geometry/materials/confidence/evidence (note: `world_ir.diff.diff_worlds()` + `reality diff` CLI already exist per prior sessions — verify against current code before assuming this is unstarted)
28. Branching — connect existing simulation branching infra to WorldIR (REAL WORLD → World v1 → Branch A/B scenarios)

## P5 — Simulation integration
29. WorldIR → Physics compile (bodies/collision geometry/materials/constraints) — note: `engine/physics/world_compiler.py` already exists per 2026-09-13 session; verify scope against this item before assuming unstarted
30. Physics → WorldIR — post-simulation state back into geometry/entities/events/WorldIR (currently incomplete per user)
31. Better physics — CCD, angular contact response, stronger contact manifolds, constraints/joints, structural mechanics, fluid sim, fire/thermal coupling, environment coupling (explicitly lower priority than the mapping spine)

## P6 — Reality Studio
32. Real Studio application — viewport/outliner/inspector/source browser/evidence browser/measurement/transform tools/provenance/uncertainty/timeline/diff/branching/simulation UI
33. Real mesh renderer — beyond point-cloud+AABB: real triangle mesh, materials, textures, lighting, camera nav, LOD
34. Measurement system — click A/B → distance, eventually with uncertainty + source attribution
35. Evidence visualization — click an entity → supporting photos/LiDAR points/camera poses/measurements/confidence/uncertainty/provenance

## P7 — Scale / production engineering
36. Large-world architecture — tiles/cells/streaming/LOD/spatial indexes/GPU accel/out-of-core clouds+meshes
37. Spatial acceleration — current index is flat/O(n); need BVH/KD-tree/Octree/R-tree/voxel hierarchy per workload
38. GIS integration — CRS/GeoTIFF/DEM/DTM/DSM/orthophoto/terrain/coordinate transforms/georeferencing, WorldIR↔GIS
39. Robotics integration — ROS export/consumption, robot trajectories, occupancy maps, point clouds, nav maps, sensor frames
40. Plugin/backend architecture — DepthBackend/ReconstructionBackend/SegmentationBackend/DetectionBackend/RegistrationBackend/MeshingBackend as discoverable plugins, not hard-coded

## P8 — Production release
41. CI — unit/integration/packaging/CLI/security/lint/type-check
42. Real-data CI — golden dataset continuously verifying photo→reconstruction→WorldIR
43. Model reproducibility — `ModelRegistry` (version/checkpoint/SHA256/preprocessing/runtime/license) instead of uncontrolled `torch.hub` downloads
44. Blender/USD real verification — actually open/inspect/validate geometry+units+transforms in Blender/USD, not just "export returned successfully"
45. Performance benchmarks — real numbers at 100/500/1000 images, 1M/10M/100M points, video ingestion, depth inference, mesh reconstruction, WorldIR compilation, session load, Studio render
46. Security audit — uploaded files, archives, paths, subprocesses, COLMAP, model downloads, artifact store, serialization, plugins, CLI, temp files
